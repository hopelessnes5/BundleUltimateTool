# BundleUltimateTool — план проекта

## Цель и ограничения

Новое Windows-приложение для полного цикла работы с архивами NFS:HP / Burnout Paradise
(`.bundle`, `.bndl`): обзор, извлечение, предпросмотр и конвертация текстур, экспорт
моделей, просмотр STRINGS-таблиц, сборка/пересборка архивов.

- **Стек:** C# 13 / .NET 9 (`net9.0-windows`), WinForms, один EXE.
- **Интерфейс:** компактная оболочка в стиле PrototypeUltimateTool — одно основное окно
  редактора, меню, панель команд, дерево ресурсов, сетка свойств, строка состояния,
  светлая/тёмная темы, RU/EN-каталоги, недавние файлы, журнал.
- **Форматы:** логика портируется с C++/Qt (`nfs-bundle-explorer`) на managed C#.
- **Поставка:** framework-dependent single-file publish; .NET 9 Windows Desktop Runtime
  устанавливается отдельно, self-contained не использовать.
- **Исходники не трогаем:** `F:\repos\PrototypeUltimateTool` и
  `F:\repos\nfs-bundle-explorer` остаются эталоном (оба репозитория чистые).

## Критерии приёмки сборщика (S3)

- Сборка **без замен** из эталонного архива должна дать побайтово тот же файл:
  исходные сжатые заголовки/тела переиспользуются как есть, смещения и размеры не меняются.
- Сборка **с заменой** `.nfs`: новый архив открывается нашим ридером, число записей то же,
  заменённая запись декомпрессируется в содержимое `.nfs` (32-байтный NFS-заголовок + тело),
  остальные записи декомпрессируются в байты, идентичные оригиналу.
- Побайтовое совпадение **новых** zlib-потоков с ожидаемым не требуется (другая версия zlib),
  но отрицать difference в отчёте нельзя — он фиксируется в логе.
- Обязательно исправить баг оригинала: `AssembleBundle` писал `<path>.temp` и никогда не
  переименовывал результат. Наш порт пишет во временный файл и затем атомарно заменяет цель.
- `MemoryMappedFile` исходника должен быть закрыт до замены файла, иначе на Windows замена
  заблокируется.

## Правила ведения

- Анализ и код поручаются субагенту Iceman (English-only); главный агент держит контекст,
  ставит задачи по одной и проверяет результат.
- Одно логическое изменение → сборка/проверка → следующая задача.
- Каждый этап завершается реальной сборкой; статический анализ не выдаётся за сборку.
- Сохранять компактность UI: никаких просторных отступов и лишних заголовков над
  деревом/свойствами.
- Не копировать бинарные ресурсы и текстуры без необходимости; оригинальные имена
  ресурсов сохранять.
